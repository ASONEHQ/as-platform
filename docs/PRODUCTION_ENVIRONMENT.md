# AS ONE — Production Environment Reference

TASK 14.1, section B. A complete, per-variable reference for every
environment variable `packages/config/src/index.ts` reads, generated by
reading that file in full (both `sharedSchema`, used by `apps/api` and
`apps/worker`, and the `apiSchema` extension used by `apps/api` only) and
cross-referenced against `docs/PRODUCTION_GAPS.md` (TASK 14.0's forensic
audit of this same code). This document also incorporates the production
database-TLS policy added in this task (section C below), which
`docs/PRODUCTION_GAPS.md` §5 had flagged as a real, unfixed gap.

**Re-verified at TASK 15.0 Phase 9** (RC certification) against current
HEAD: every table below was re-checked directly against
`packages/config/src/index.ts` and remains accurate as written. The one
real change since TASK 14.1 is TASK 14.5A's branding/object-storage
dependency, documented in its own new section below and in
`docs/RC_PRODUCTION_CONFIG.md`.

## How to read this document

- **Required** means `loadApiConfig()`/`loadWorkerConfig()` throws
  (`apiSchema.parse(environment)` / `sharedSchemaWithProductionChecks.parse(environment)`,
  both plain Zod `.parse()`, which throws a `ZodError` on any missing or
  invalid value) if the variable is absent or malformed.
- **Startup fails closed?** — confirmed by reading the actual call site,
  `apps/api/src/server.ts`'s `startServer()`: `loadApiConfig()` is called
  inside a `try/catch`; on failure it writes `API configuration is invalid.`
  to stderr, sets `process.exitCode = 1`, and **returns without ever calling
  `app.listen()`**. There is no partially-configured boot path — every
  required variable (and every production-only constraint below) is
  fail-closed by construction, not by convention. `apps/worker` follows the
  same pattern via `loadWorkerConfig()`.
- Every "production constraint" row below is enforced only when
  `NODE_ENV === 'production'` — local (`asone_local`) and test
  (`asone_...test...`) environments are never affected by a production-only
  rule. This mirrors the existing `AUTH_ACCESS_TOKEN_SECRET` strength check,
  which is the template this task's own DB-TLS rule (section C) copies.

## Shared variables (`apps/api` and `apps/worker`)

These come from `sharedSchema` in `packages/config/src/index.ts` and are
validated identically for both processes via `loadApiConfig()` and
`loadWorkerConfig()`.

### `NODE_ENV`

- **Required.** Enum: `development` | `test` | `production`.
- **Purpose.** Selects every environment-scoped behavior in this table
  (production-only secret strength, production-only DB TLS enforcement,
  `Secure`/`__Host-` cookie flags in `apps/api/src/modules/auth`, default
  `METRICS_ENABLED`/`OPENAPI_UI_ENABLED`, etc.).
- **Example.** `production`
- **Production constraint.** N/A — this variable defines what "production"
  means to every other check.
- **Failure mode.** Missing or any other string: `ZodError`, boot refused.
- **Fails closed?** Yes.

### `APP_NAME`

- **Required.** Non-empty string (trimmed).
- **Purpose.** Reported in `GET /health` and used as the logger's `service`
  name.
- **Example.** `asone-api`
- **Production constraint.** None beyond non-empty.
- **Failure mode.** Missing/empty: boot refused.
- **Fails closed?** Yes.

### `APP_VERSION`

- **Required.** Non-empty string (trimmed).
- **Purpose.** Reported in `GET /health`; useful for release correlation in
  logs/dashboards.
- **Example.** `1.4.2` or a git SHA such as `a1b2c3d`
- **Production constraint.** None beyond non-empty.
- **Failure mode.** Missing/empty: boot refused.
- **Fails closed?** Yes.

### `LOG_LEVEL`

- **Required.** Enum: `fatal` | `error` | `warn` | `info` | `debug` |
  `trace` | `silent`.
- **Purpose.** Pino log level. `packages/logger` redacts
  `authorization`/`cookie`/`password`/tokens/secrets/`database_url`/
  `redis_url` and query strings regardless of level (see
  `docs/PRODUCTION_GAPS.md` §8) — this variable only controls verbosity,
  never what gets redacted.
- **Example.** `info`
- **Production constraint.** None enforced in code; operationally `info` or
  `warn` is the sane production choice (`debug`/`trace` are noisy, `silent`
  would hide incidents).
- **Failure mode.** Missing or an unrecognized level: boot refused.
- **Fails closed?** Yes.

### `DATABASE_URL`

- **Required.** Must be a valid URL starting with `postgresql://`.
- **Purpose.** The single Postgres connection string, used to build the
  `pg.Pool` in `packages/database/src/client.ts` (via
  `apps/api/src/infrastructure/dependencies.ts` for the API and
  `apps/worker/src/infrastructure.ts` for the worker).
- **Example.** `postgresql://app_user:REDACTED@db.internal:5432/asone_prod?sslmode=verify-full`
- **Production constraint — DB TLS policy (this task, section C).**
  Previously nothing in code required TLS; it depended entirely on an
  operator remembering to add `sslmode=require` (or similar) themselves,
  completely unvalidated (`docs/PRODUCTION_GAPS.md` §5). Now, in
  `NODE_ENV === 'production'` only:
  - `DATABASE_URL` must include `sslmode=require`, `sslmode=verify-ca`, or
    `sslmode=verify-full` as a query parameter, **or**
  - `DATABASE_TLS_EXTERNALLY_TERMINATED=true` must be set explicitly (see
    below) for the documented case where TLS is terminated outside the `pg`
    driver entirely.
  - Anything else (`sslmode` missing, or explicitly `sslmode=disable`, with
    no override) is rejected at config-validation time — fail closed, same
    `.superRefine` pattern as `AUTH_ACCESS_TOKEN_SECRET` below, applied to
    both `apiSchema` (API) and the shared schema (worker), so the worker's
    Postgres pool is held to the identical policy.
  - The resolved `sslmode` is also threaded into the **real** `pg.Pool`
    construction (`packages/database/src/client.ts`), not just validated as
    a string — `sslOptionForMode()` translates it into `pg`'s own `ssl`
    option: `verify-ca`/`verify-full` → `{ rejectUnauthorized: true }`
    (certificate-verified, the safe default); `require` →
    `{ rejectUnauthorized: false }` (encrypted, verification skipped — the
    documented escape hatch for a managed Postgres provider — e.g. Amazon
    RDS/Aurora, Azure Database for PostgreSQL, or DigitalOcean Managed
    Databases — whose server certificate is not in Node's default CA
    bundle; prefer `verify-full`/`verify-ca` with the provider's CA
    certificate whenever it is available instead); `disable` → `false`.
  - `asone_local`/`asone_test` (loopback Postgres, no TLS) are completely
    unaffected — the rule is scoped to `NODE_ENV === 'production'` only.
- **Failure mode.** Missing/malformed URL: boot refused (always). In
  production, TLS not requested and no override set: boot refused
  (`DATABASE_URL must request TLS in production: add sslmode=require, ...`).
- **Fails closed?** Yes, in every case above.

### `DATABASE_TLS_EXTERNALLY_TERMINATED`

- **Optional.** `'true'` | `'false'`, defaults to `false`.
- **Purpose.** Explicit escape hatch from the `DATABASE_URL` TLS
  requirement above, for the real architecture where the TLS-terminating
  hop is not the `pg` driver itself — e.g. a Cloud SQL Auth Proxy or an
  `stunnel` sidecar the app connects to over a local socket/loopback
  address, with the sidecar carrying the encrypted connection onward. In
  that topology `DATABASE_URL` correctly has no `sslmode` parameter, and
  the plain `DATABASE_URL` check would otherwise reject a legitimately
  secure setup.
- **Example.** `true`
- **Production constraint.** Only meaningful in production (see
  `DATABASE_URL` above); defaults to `false`, so the default posture is
  fail-closed — an operator must opt in explicitly, never opt out silently.
- **Failure mode.** N/A (optional, has a safe default).
- **Fails closed?** N/A (this variable widens, never narrows, what passes
  validation — and only when explicitly set).

### `REDIS_URL`

- **Required.** Must be a valid URL starting with `redis://` or `rediss://`
  (TLS).
- **Purpose.** Builds a `redis` v4 client (`createClient()`), used **only**
  by `GET /ready`, the operations CLI (`apps/api/src/operations/cli.ts`,
  `operational-checks.service.ts`), and `apps/worker`'s own readiness check
  — confirmed by grepping every module under `apps/api/src/modules`
  (auth, sales, cash, payments, refunds, promotions, loyalty, rewards): none
  of them reference Redis. **Redis is required to boot** (the URL must
  parse) **but not required to serve the core POS flow** (login → sale →
  payment → receipt), which is Postgres-only. This is exactly why this
  task's section D change makes `GET /ready`'s HTTP status gate on Postgres
  alone while still reporting Redis's own state honestly in the response
  body and the `asone_readiness_dependency{service="redis"}` gauge.
- **Example.** `redis://cache.internal:6379`
- **Production constraint.** None beyond a well-formed URL with the
  `redis://` or `rediss://` scheme — TLS is not *required* by the schema
  (Redis is not authoritative data per `docs/DISASTER_RECOVERY.md`'s T3
  classification), but a `rediss://` value (used by every DigitalOcean
  Managed Valkey/Redis cluster, which mandates TLS) is now accepted.
  **TASK 16.2D:** a prior re-verification pass (Phase 9, see history below)
  had flagged that the schema check was a literal `.startsWith('redis://')`
  (exact 8-character prefix), which meant a real `rediss://` connection
  string would **fail** validation outright
  (`"rediss://x".startsWith("redis://")` is `false`) — this is exactly what
  caused a real DigitalOcean production boot to fail with an opaque "API
  configuration is invalid." error and no visible reason. Fixed by widening
  the check to a `.refine()` accepting both `redis://` and `rediss://`
  (`packages/config/src/index.ts`); `server.ts`'s startup catch block was
  also changed to print the failing config key and a sanitized constraint
  description (never the raw value) instead of swallowing the error, so a
  future misconfiguration is diagnosable from the DigitalOcean runtime logs
  directly.
- **Failure mode.** Missing/malformed URL: boot refused. At runtime, an
  unreachable Redis degrades `/ready`'s reported `services.redis` to
  `unavailable` and the CLI's `check`/`readiness` commands, but no longer
  fails the HTTP readiness status or the core POS request path.
- **Fails closed?** Yes, at boot (URL must parse). At runtime, Redis being
  down is now a soft/reported failure only, by design (section D).

## `apps/api`-only variables

These extend `sharedSchema` into `apiSchema` and only apply to
`apps/api` (the worker never reads them).

### `API_HOST`

- **Required.** Non-empty string.
- **Purpose.** Interface Fastify binds to (`app.listen({ host, port })`).
- **Example.** `0.0.0.0` (container) or `127.0.0.1` (behind a local proxy)
- **Production constraint.** None enforced in code; operationally must
  match the container/network topology.
- **Failure mode.** Missing: boot refused.
- **Fails closed?** Yes.

### `API_PORT`

- **Required.** Integer, coerced from string, `1`–`65535`.
- **Purpose.** Port Fastify listens on.
- **Example.** `3000`
- **Production constraint.** None beyond range.
- **Failure mode.** Missing/out of range/non-numeric: boot refused.
- **Fails closed?** Yes.

### `AUTH_ACCESS_TOKEN_SECRET`

- **Required.** String, minimum 32 characters.
- **Purpose.** The single secret used for both JWT access tokens and
  refresh-token HMACs (`apps/api/src/modules/auth/auth.tokens.ts`) — the
  most security-critical variable in this table.
- **Example.** A high-entropy random string, e.g. output of
  `openssl rand -base64 48` — never a real value in this document.
- **Production constraint.** Beyond `.min(32)`, a `.superRefine` rejects any
  value that is low-entropy (fewer than 4 distinct characters, e.g. 40
  repeated `a`s) or contains a known placeholder token (`changeme`,
  `replace_me`, `placeholder`, `example`, `your_secret`, `local_only`,
  `todo`, etc. — see `weakSecretPlaceholders` in
  `packages/config/src/index.ts`). Scoped to `NODE_ENV === 'production'`
  only; dev/test fixtures using a readable literal are unaffected.
- **Failure mode.** Missing/too short: boot refused (all environments). In
  production, low-entropy or placeholder-like: boot refused
  (`AUTH_ACCESS_TOKEN_SECRET must not be a low-entropy or placeholder value
  in production.`).
- **Fails closed?** Yes, in every case above.

### `AUTH_ACCESS_TOKEN_TTL_SECONDS`

- **Optional.** Integer, `60`–`3600`, default `900` (15 minutes).
- **Purpose.** Access token lifetime.
- **Example.** `900`
- **Production constraint.** Range-bounded only.
- **Failure mode.** Out of range: boot refused. Unset: default applies.
- **Fails closed?** Yes if set invalidly; otherwise defaults safely.

### `AUTH_JWT_AUDIENCE`

- **Required.** Non-empty string.
- **Purpose.** JWT `aud` claim, validated on every authenticated request.
- **Example.** `asone-api-prod`
- **Production constraint.** None beyond non-empty.
- **Failure mode.** Missing: boot refused.
- **Fails closed?** Yes.

### `AUTH_JWT_ISSUER`

- **Required.** Non-empty string.
- **Purpose.** JWT `iss` claim, validated on every authenticated request.
- **Example.** `https://api.asone.mx`
- **Production constraint.** None beyond non-empty.
- **Failure mode.** Missing: boot refused.
- **Fails closed?** Yes.

### `AUTH_LOGIN_RATE_LIMIT_MAX`

- **Optional.** Integer, `1`–`100`, default `10`.
- **Purpose.** Max login attempts per window before rate limiting.
- **Example.** `10`
- **Production constraint.** Range-bounded only.
- **Failure mode.** Out of range: boot refused. Unset: default applies.
- **Fails closed?** Yes if set invalidly; otherwise defaults safely.

### `AUTH_LOGIN_RATE_LIMIT_WINDOW_MS`

- **Optional.** Integer, `1000`–`3_600_000`, default `60000` (1 minute).
- **Purpose.** Rate-limit window for login attempts.
- **Example.** `60000`
- **Production constraint.** Range-bounded only.
- **Failure mode.** Out of range: boot refused. Unset: default applies.
- **Fails closed?** Yes if set invalidly; otherwise defaults safely.

### `AUTH_REFRESH_TOKEN_TTL_SECONDS`

- **Optional.** Integer, `3600`–`31_536_000`, default `2_592_000` (30 days).
- **Purpose.** Refresh token / session lifetime.
- **Example.** `2592000`
- **Production constraint.** Range-bounded only.
- **Failure mode.** Out of range: boot refused. Unset: default applies.
- **Fails closed?** Yes if set invalidly; otherwise defaults safely.

### `CORS_ALLOWED_ORIGINS`

- **Optional.** Comma-separated list of absolute URLs, default
  `http://localhost:3000,http://127.0.0.1:3000`. Wildcards (`*`) and any
  non-parseable entry are rejected outright (`corsOriginsSchema`), and the
  resulting list is de-duplicated and frozen.
- **Purpose.** The exact allow-list `@fastify/cors` (`origin()` callback)
  and the independent browser-auth-route origin check
  (`requireApprovedOrigin`) both read from — no `origin: true`/`*` path
  exists anywhere in code (`docs/PRODUCTION_GAPS.md` §2).
- **Example.** `https://app.asone.mx,https://pos.asone.mx`
- **Production constraint.** None enforced in code beyond "no wildcard, all
  must parse as URLs" (same in every environment) — but an operator who
  forgets to set this in production ships an API that rejects every real
  browser origin (fails closed, not open, since the default is
  localhost-only).
- **Failure mode.** A literal `*` or an unparseable entry: boot refused in
  every environment. Simply unset in production: boots, but no real browser
  origin will be allowed through CORS until corrected.
- **Fails closed?** Yes for malformed input; the "forgot to set it" case
  fails closed toward rejecting traffic, not toward `*`.

### `KEEP_ALIVE_TIMEOUT_MS`

- **Optional.** Integer, `1000`–`120_000`, default `72000`.
- **Purpose.** HTTP keep-alive timeout (should exceed the upstream load
  balancer's idle timeout to avoid connection races).
- **Example.** `72000`
- **Production constraint.** Range-bounded only.
- **Failure mode.** Out of range: boot refused. Unset: default applies.
- **Fails closed?** Yes if set invalidly; otherwise defaults safely.

### `METRICS_ENABLED`

- **Optional.** `'true'` | `'false'`, no schema default — `loadApiConfig()`
  itself defaults it to `NODE_ENV === 'development'` when unset.
- **Purpose.** Toggles the `/metrics` Prometheus endpoint.
- **Example.** `true`
- **Production constraint.** None enforced; defaults to `false` in
  production unless explicitly set — an operator who wants metrics scraped
  in production must set this explicitly.
- **Failure mode.** Invalid value (not `'true'`/`'false'`): boot refused.
  Unset: defaults per environment.
- **Fails closed?** Yes if set invalidly; the unset default leans toward
  "off" outside development, not toward exposing an unauthenticated
  endpoint unexpectedly.

### `OPENAPI_UI_ENABLED`

- **Optional.** `'true'` | `'false'`, no schema default — defaults to
  `NODE_ENV === 'development'` when unset, identical pattern to
  `METRICS_ENABLED`.
- **Purpose.** Toggles `/documentation` (Swagger UI). Also gates Content
  Security Policy: `apps/api/src/plugins/security.ts` disables CSP whenever
  `openapiUiEnabled` is `false` (the default outside development) — see
  `docs/PRODUCTION_GAPS.md` §12 (flagged POST-LAUNCH, not changed by this
  task; low practical impact since `apps/api` serves JSON, not HTML, but
  worth an operator's awareness).
- **Example.** `false`
- **Production constraint.** None enforced; defaults to `false` in
  production unless explicitly set.
- **Failure mode.** Invalid value: boot refused. Unset: defaults per
  environment.
- **Fails closed?** Yes if set invalidly; unset defaults toward "off"
  outside development.

### `RATE_LIMIT_MAX`

- **Optional.** Integer, `1`–`100_000`, default `300`.
- **Purpose.** Global per-window request rate limit
  (`@fastify/rate-limit`, in-memory store — no Redis-backed store is
  configured, see `REDIS_URL` above).
- **Example.** `300`
- **Production constraint.** Range-bounded only.
- **Failure mode.** Out of range: boot refused. Unset: default applies.
- **Fails closed?** Yes if set invalidly; otherwise defaults safely.

### `RATE_LIMIT_WINDOW_MS`

- **Optional.** Integer, `1000`–`3_600_000`, default `60000`.
- **Purpose.** Window for the global rate limit above.
- **Example.** `60000`
- **Production constraint.** Range-bounded only.
- **Failure mode.** Out of range: boot refused. Unset: default applies.
- **Fails closed?** Yes if set invalidly; otherwise defaults safely.

### `REQUEST_BODY_LIMIT_BYTES`

- **Optional.** Integer, `1024`–`10_485_760` (10 MiB), default `1_048_576`
  (1 MiB).
- **Purpose.** Max accepted request body size.
- **Example.** `1048576`
- **Production constraint.** Range-bounded only.
- **Failure mode.** Out of range: boot refused. Unset: default applies.
- **Fails closed?** Yes if set invalidly; otherwise defaults safely.

### `REQUEST_TIMEOUT_MS`

- **Optional.** Integer, `1000`–`120_000`, default `30000`.
- **Purpose.** Per-request timeout.
- **Example.** `30000`
- **Production constraint.** Range-bounded only.
- **Failure mode.** Out of range: boot refused. Unset: default applies.
- **Fails closed?** Yes if set invalidly; otherwise defaults safely.

### `TRUST_PROXY`

- **Optional.** `'true'` | `'false'`, default `false`.
- **Purpose.** Passed straight into Fastify's `trustProxy` option, which
  governs whether `X-Forwarded-For` (used by `@fastify/rate-limit`'s
  default IP-based key generator) is trusted. No application code reads
  `request.ip`/`request.protocol` directly (`docs/PRODUCTION_GAPS.md` §4).
- **Example.** `true` (when deployed behind a real reverse proxy/load
  balancer)
- **Production constraint.** None enforced in code; operationally, deploying
  behind a real proxy without setting this to `true` degrades
  rate-limiting accuracy (every request looks like it comes from the
  proxy's IP) — it does not open a spoofing hole, since the unsafe
  direction (trusting forwarded headers with no real proxy in front)
  requires this explicit opt-in.
- **Failure mode.** Invalid value: boot refused. Unset: defaults to `false`
  (safe direction).
- **Fails closed?** Yes if set invalidly; the unset default is the safe
  direction, not the unsafe one.

### `MERCADO_PAGO_ACCESS_TOKEN`

- **Optional.** Non-empty string, no default.
- **Purpose.** Mercado Pago Point provider credential (TASK 12.4B.1).
  Deliberately optional — the app must still boot with no payment provider
  configured (local dev, CI, a company that hasn't set up Point yet).
- **Example.** A provider-issued access token — never a real value here.
- **Production constraint.** None at config-validation time. The specific
  provider call fails cleanly and explicitly
  (`PaymentProviderError('not_configured', ...)`) only when actually
  invoked without it — see `apps/api/src/modules/payments/providers/mercado-pago.provider.ts`
  (outside this task's editable scope; documented here for completeness).
- **Failure mode.** Missing: boot proceeds; the specific Mercado Pago Point
  call fails at request time with an explicit `not_configured` error, not a
  silent no-op.
- **Fails closed?** At the point of use, yes (explicit error, not silent
  fallback). Not required at boot.

### `MERCADO_PAGO_WEBHOOK_SECRET`

- **Optional.** Non-empty string, no default.
- **Purpose.** Verifies inbound Mercado Pago webhook signatures.
- **Example.** A provider-issued webhook secret — never a real value here.
- **Production constraint.** None at config-validation time (same reasoning
  as `MERCADO_PAGO_ACCESS_TOKEN` above).
- **Failure mode.** Missing: boot proceeds; webhook handling fails cleanly
  at request time if actually invoked without it.
- **Fails closed?** At the point of use, yes. Not required at boot.

### `MERCADO_PAGO_API_BASE_URL`

- **Optional.** Valid URL, default `https://api.mercadopago.com`.
- **Purpose.** Base URL for Mercado Pago API calls — overridable for a
  sandbox/staging environment.
- **Example.** `https://api.mercadopago.com` (production) or a sandbox host
  in lower environments.
- **Production constraint.** Must be a well-formed URL if set; otherwise the
  production default is already correct.
- **Failure mode.** Malformed URL: boot refused. Unset: safe default
  applies.
- **Fails closed?** Yes if set invalidly; otherwise defaults safely.

## Object storage (MinIO/S3-compatible) — business logo + product images — TASK 14.5A / 16.6 / 16.6A, real but outside `packages/config`

TASK 14.5A wired a real dependency this document's TASK 14.1 version did
not yet have: business-logo upload/delete
(`apps/api/src/modules/admin/branding/`) against MinIO's S3-compatible
API. TASK 16.6 added a second, real consumer of the SAME configuration —
product-image upload/delete (`apps/api/src/modules/catalog/product-images
.storage.ts`) — by generalizing the branding class into a shared
`S3ObjectStorage` (`apps/api/src/infrastructure/object-storage.ts`); TASK
16.6A then refactored `BrandingObjectStorage` itself to compose that same
shared class (previously a hand-duplicated copy), so there is now exactly
ONE object-storage implementation behind both features, reading exactly
ONE set of environment variables. Re-verified at TASK 15.0 Phase 9 by
reading the actual code path (not just its own doc comment) — see
`docs/RC_PRODUCTION_CONFIG.md` section 5 for the original evidence trail
and `docs/PRODUCTION_OBJECT_STORAGE_SETUP.md` for the concrete
DigitalOcean-compatible provisioning plan. The short version:

- `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `MINIO_API_PORT` are real,
  consumed environment variables — read directly via `process.env` by
  `objectStorageConfigFromEnv()`
  (`apps/api/src/infrastructure/object-storage.ts`; both
  `brandingStorageConfigFromEnv` and `productImageStorageConfigFromEnv`
  are now plain re-exports of this one function), **not** through the
  Zod-validated `packages/config` schema (they are not, and as of this
  task still are not, declared in `sharedSchema`/`apiSchema`). This is a
  deliberate architectural choice mirroring `MERCADO_PAGO_ACCESS_TOKEN`'s
  own "optional external dependency, fails cleanly when actually invoked"
  pattern, applied at the route-registration boundary instead of at
  request time.
- **TASK 16.6A — `MINIO_ENDPOINT` (new, optional, fourth variable)**: a
  real, full base URL (e.g. `https://nyc3.digitaloceanspaces.com`) for a
  genuinely remote S3-compatible endpoint — a self-hosted MinIO NOT
  co-located with the API host, or a managed provider such as
  DigitalOcean Spaces. When present and well-formed (`http://`/`https://`
  only), it REPLACES the previous hardcoded `http://127.0.0.1:{MINIO_API
  _PORT}` construction entirely for BOTH features. When absent (every
  deployment before this task, and any production host that never sets
  it), behavior is byte-for-byte unchanged — this is purely additive. A
  malformed `MINIO_ENDPOINT` makes `objectStorageConfigFromEnv()` return
  `undefined` (the same "not configured" outcome as a missing
  credential), never a confusing runtime S3-client error deep inside an
  upload request.
- **All four are optional as a group, with a fail-open-to-absent (never
  fail-closed-to-crash) posture**: `objectStorageConfigFromEnv()` returns
  `undefined` — a normal value, never a thrown error — when either
  required credential is missing/empty, the port is invalid, or
  `MINIO_ENDPOINT` (when set) is malformed.
  `apps/api/src/bootstrap/register-plugins.ts` only calls
  `registerBrandingRoutes(...)` / passes a real `ProductImageStorage`
  into `registerProductCatalogRoutes(...)` when that value is defined;
  when it is `undefined`, the branding routes are skipped entirely and
  the two product-image routes (`POST`/`DELETE .../products/:id/image`)
  are simply never registered — every other route in `registerPlugins`
  (auth, sales, cash, payments, refunds, inventory, customers, loyalty,
  rewards, reports, dashboard, the rest of the product-catalog module,
  and everything else) registers exactly as it always does. There is no
  `try/catch` anywhere in this path because nothing in it can throw.
- **Practical effect**: with no `MINIO_*` variables set, the API boots
  normally and every POS capability except the branding routes AND the
  two product-image routes works. Those routes simply don't exist — a
  request to any of them gets Fastify's ordinary 404 for an unmatched
  route, not a 503 or a crash. The Flutter app surfaces this honestly:
  `_EditProductDialog`/`PosBrandingScreen` show a real "El almacenamiento
  de imágenes no está disponible en este servidor. Contacta a soporte."
  message on that 404 (TASK 16.6A) rather than a generic error or (worse)

## Flutter app (`apps/one`) — build-time, not a server env var

`AS_API_BASE_URL` (and its siblings `AS_ENV`, `AS_APP_NAME`,
`AS_ENABLE_TELEMETRY`) are **not** read from `process.env` by any server
process — they are Flutter `--dart-define` **build-time** values, baked
into the compiled app at build time, consumed in
`apps/one/lib/core/config/app_config.dart`'s `AppConfig.fromEnvironment()`:

- `AS_ENV` — one of `local`/`test`/`staging`/`demo`/`production`, default
  `local`. Throws (`StateError`) at app startup if unrecognized.
- `AS_API_BASE_URL` — the API origin the compiled app talks to, default
  `http://localhost:3000`. Must be an absolute, authority-bearing URL
  (`Uri.tryParse(...).hasAuthority`), and **must use HTTPS whenever
  `AS_ENV` is not `local`** — enforced by a `StateError` thrown at startup,
  not merely documented convention.
- `AS_APP_NAME` — display name, default `AS ONE`.
- `AS_ENABLE_TELEMETRY` — boolean, default `false`.

Example production build invocation (illustrative shape only):

```
flutter build web \
  --dart-define=AS_ENV=production \
  --dart-define=AS_API_BASE_URL=https://api.asone.mx \
  --dart-define=AS_APP_NAME="AS ONE"
```

This file documents these for completeness per this task's instructions,
but `apps/one` itself is out of this task's editable scope — nothing under
`apps/one` was changed.
